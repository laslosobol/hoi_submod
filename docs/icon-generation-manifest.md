# Cyanolisia icon manifest

This is the authoritative Cyanolisian icon register. The focus section inventories every focus in
`CYA.txt`, `HSM_CYA_development.txt`, and `HSM_CYA_development_expansion.txt`.
`art/README.md` keeps historical source descriptions, not completion status.
The national-spirit section below inventories uses in `HSM_CYA_ideas.txt`.
Leader portraits and flags are separate art types and are not counted here.

The inventory scripts and self-contained tests require **PowerShell 7.2+ on
Windows**. Run them with `pwsh`, not Windows PowerShell 5.1:
`pwsh -NoProfile -File tools/Test-CyanolisiaIconManifest.ps1`,
`pwsh -NoProfile -File tools/Update-CyanolisiaIconManifest.ps1 -Check`, and
`pwsh -NoProfile -File tools/Update-CyanolisiaSpiritManifest.ps1 -Check`.

## Status and paths

- `DONE`: decodable transparent PNG, valid transparent TGA, correct GFX reference, recorded
  visual/lore review, and SHA-256 baselines for **both** files. This is not
  in-game QA. Focus exports are 99x86; spirit exports are 64x64.
- `NEEDS_REVIEW`: linked art needs visual confirmation, or a previously approved
  PNG/TGA changed. The old QA hashes remain until explicit reapproval.
- `NEEDS_FIX`: technical integration is broken or an artistic defect is still
  open. A passing technical check alone never clears a manual art defect.
- `MISSING`: planned custom PNG/TGA do not yet exist; the GFX column shows the
  current provisional icon, not a custom sprite. Planned paths are explicit.
- `NOT_REQUIRED`: separate custom focus art deliberately unnecessary.
- `CYA`, `DEV`, `EXP` mean the three focus files named above. Paths are relative
  to the repository root. New custom focus sprites use `GFX_<art key>`.
- `QA PNG SHA-256` and `QA TGA SHA-256` are the *approved* file versions, not
  a live checksum cache. `Technical` is machine-maintained; References,
  Composition / heraldry, and Defect / next are retained on ordinary sync.
  PNG sources must decode, be at least export size (at most 8192x8192), and
  include transparent and opaque pixels. Hash matches alone do not validate format.

## Working rules

1. Before a new batch, read this register and choose 8-12 `MISSING` rows.
   Check those IDs and any changed files only; do not repeat the full audit.
2. Do one semantic pass for the batch: focus effects, English/Russian names and
   descriptions, relevant EaW lore and flags. Reuse the references below and
   each row's existing art brief. Do not infer a flag from a country name.
3. Generate distinct painted HOI4 emblems with one dominant silhouette and at
   most two supporting motifs. Palette: dark iron, antique gold, ivory,
   slate/cobalt blue, restrained crimson. Exterior transparent. No invented
   heraldry, human hands, disproportionate griffon anatomy, blank seals or
   vacant documents; no pseudo-text. Grover's pointed coronet is not a
   fleur-de-lis crown. Keep symbols legible at game size.
4. Export with `tools/Convert-ToHoi4Tga.ps1` to 99x86, register the sprite,
   update the focus icon, inspect a 99x86 contact sheet and run
   `tools/Test-CyanolisiaFocusArt.ps1` on the batch. Mark `DONE` only after
   visual/lore review and technical validation. A game test is separate.
5. Sync only changed IDs with `pwsh -NoProfile -File tools/Update-CyanolisiaIconManifest.ps1
   -FocusIds <full IDs>` (spirits use `-IdeaIds`). After actual visual review,
   add `-MarkDone` to record current PNG/TGA hashes. An existing `NEEDS_FIX`
   requires explicit `-ResolveFix`; combine it with `-MarkDone` only if the
   repaired art has also been visually approved. Neither switch is routine.
   `-ResolveFix` records the old defect as `Resolved <date>:` and replaces its
   active `Next:` action; later approval retains that history. Unresolved notes
   stay active until explicit resolution. For another defect on the same asset,
   retain prior `Resolved` notes and add `Active: <defect>; Next: <action>`
   before resolving it.
   Run each script with `-Check` for a read-only audit. No-op syncs leave the
   manifest untouched. Do not regenerate `DONE` assets without a defect.
6. The one-time `-MigrateHashes` migration pinned the 23 previously approved
   focus assets without changing their statuses. The former `-Initialize`
   bootstrap is retired; do not rerun `-MigrateHashes` during ordinary batches.
   Documentation-only edits do not
   change art approval; only PNG/TGA content hashes do.

## Canonical references and feedback

- `EaW/gfx/flags/CYA_neutrality.tga`: slate-blue field, black straight
  gold-edged cross, central gold griffon medallion. Dawnclaw's personal iron
  cross: `art/source/HSM_CYA_ferdinand_dawnclaw_portrait.png`.
- `EaW/gfx/flags/GRI_neutrality.tga`: black griffon on cream/orange quarters;
  only for genuinely imperial contexts. Directorate flag:
  `mod/HoISubmod/gfx/flags/HSM_CYA_DIRECTORATE.tga`.
- `EaW/gfx/flags/JER_neutrality.tga`: Aquileian gold lilies on burgundy.
  Use fleur-de-lis for Aquileian context, not as generic Cyanolisian or
  imperial ornament. Minor non-heraldic details are fine.
- `EaW/gfx/flags/JAS_neutrality.tga`: Asterion's white bull on a black
  gold-edged cross over burgundy, with small gold lilies in the quarters.
- Adult Grover's simple tall-pointed coronet:
  `EaW/gfx/leaders/GRI/Grover_VI_good.tga`. Neighbor heraldry varies by path:
  inspect `EaW/gfx/flags/MIT_*.tga`, `SIC_*.tga`, `JAS_*.tga` as needed.
- Prior user feedback: avoid visual style drift across EaW countries, random
  crests or gold/white griffons, human hands, empty seals/documents, and the
  disproportionate Countess portrait or odd bust-on-chair composition.
  Previously repaired examples remain noted on their rows. Do not alter those
  images in an inventory-only task.
- `Austernfischer` is a sunken battlecruiser off Thymiaushafen, not a generic
  active ship: `EaW/events/Cyanolisia Events.txt`,
  `EaW/history/units/CYA_austernfischer.txt`.
- Built-in image generation follows the installed `imagegen` SKILL.md. The
  manifest governs project-specific content and QA, not tool behavior.
